# MeetingNotess

An AI-powered meeting intelligence API. Raw meeting notes (statements grouped
by topic and speaker) go in, and a structured, executive-style report comes
out — agenda, summary, topic-wise discussion, key decisions, and tracked
action items — generated by **Google Gemini** and stored in **MongoDB**.

🔗 Live demo: [meetingmotess.vercel.app](https://meetingmotess.vercel.app)

## Features

- **AI meeting summarization** — turns raw notes into a structured JSON report (agenda, overall summary, topic-wise discussion, key insights, per-speaker summaries) using Gemini (`gemini-2.5-flash`).
- **Action item tracking across meetings** — new action items are semantically matched against tasks from previous meetings, so the same task isn't duplicated; status (`Pending` / `In Progress` / `Completed`) carries forward.
- **Speaker & topic grouping** — meeting notes are grouped by topic, with each statement attributed to the correct speaker.
- **Persistent storage** — generated summaries and task history are saved back to MongoDB for future meetings to reference.
- **REST API** built with FastAPI, deployable as a serverless function on Vercel.

## Tech Stack

- **Backend:** FastAPI
- **Database:** MongoDB (via `pymongo` / `motor`)
- **LLM:** Google Gemini (`google-generativeai`)
- **Deployment:** Vercel (`vercel.json`)

## Setup

### 1. Clone the repo
```bash
git clone https://github.com/moizghazanfarali-hash/MeetingNotess.git
cd MeetingNotess
```

### 2. Create a virtual environment & install dependencies
```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Configure environment variables
Create a `config.py` (or `.env`, depending on how you wire it up) with:
```python
MONGO_URL = "your_mongodb_connection_string"
GEMINI_API_KEY = "your_gemini_api_key"
```
- MongoDB connection string: from [MongoDB Atlas](https://www.mongodb.com/cloud/atlas) or a local instance.
- Gemini API key: from [Google AI Studio](https://aistudio.google.com/app/apikey).

### 4. Run the server
```bash
uvicorn main:app --reload
```
The API will be available at `http://localhost:8000`.

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/` | List all raw meeting notes |
| `GET` | `/specific_meeting/{meeting_id}` | Get notes + agenda for a specific meeting |
| `GET` | `/meeting/{meeting_id}` | Generate (and save) an AI summary for a meeting, with carried-over action items from past meetings |
| `GET` | `/summary` | List all previously generated action items across meetings |

## How It Works

1. Meeting statements (per speaker, per topic) are pulled from MongoDB and grouped by topic.
2. Action items from earlier meetings are collected as task history.
3. A structured prompt — with strict rules against hallucinating speakers, decisions, or facts — is sent to Gemini, instructing it to return summary JSON only.
4. Gemini's response is parsed, given a `task_id` per action item, and saved to the `niaz_meeting_summaries` collection for future runs to reference.

## Deployment

The project includes a `vercel.json`, so it can be deployed directly to [Vercel](https://vercel.com) as a Python serverless function. Set `MONGO_URL` and `GEMINI_API_KEY` as environment variables in the Vercel project settings.
